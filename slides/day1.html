The one thing to remember

The debugging loop

1. REPRODUCE     make it fail on demand
2. HYPOTHESISE   write it down   ← ON PAPER
3. ISOLATE       prove which line
4. FIX           smallest possible change
5. VERIFY        green, nothing else broken

AI is allowed from step 3. Not before.

Step 2 is the whole workshop

Why write it down first?

If you prompt before you think, you get a confident answer to the wrong question.

And when the interviewer asks "why does this work?" — you have nothing.

A hypothesis takes 30 seconds. It is the difference between debugging and guessing.

Three tools, that's all

Print debugging

print(f"{cgpa=}")     # cgpa=7.3     name AND value
print(repr(cgpa))     # 7.300000000000001   the TRUTH
breakpoint()          # stops here.  n / c / q

repr() finds bugs that print() hides.

print(7.300000000000001) shows you 7.3. It is lying to you to be helpful.

No traceback
≠ no bug

The worst bugs don't crash.
They quietly give the wrong answer.

What breaks code in assessments

Always ask: what input breaks this?

  • empty list []
  • exactly on the boundary — is 7.0 "7.0 or above"?
  • one element
  • duplicates
  • negative numbers, zero

Boundary & off-by-one errors are the #1 cause of hidden test failures.

A green test proves
the test passed.

Not that your code is right.
